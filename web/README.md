# Aria web app

Dependency-free static frontend and Node.js API. All browser requests stay on your website origin. Server-side Supabase password login uses an HttpOnly, SameSite cookie; sessions expire after at most one hour and require sign-in again. Owner UUID is checked on every protected request. No API key reaches the browser.

See [current workspace, chat memory, screenshot input and resumable research](../docs/NOTES-WORKSPACE.md) for the implemented behavior and limits, and [automatic Obsidian sync](../docs/OBSIDIAN-SYNC.md) for one-time pairing.

## Quick Note

The **QUICK** tab captures up to 12,000 characters in Concise or Detailed mode, keeps an exact original, and files an organized copy. Only vaults explicitly enabled in **Notes → vault description → Allow Quick Note to file here** receive automatic placements. Uncertain or invalid model results go to the migration-created Unsorted vault. New notes start with AI search off; history provides the current search toggle, destination, original text, retry, and removal of pending/failed jobs.

Apply migration `supabase/008_quick_notes.sql` after 007 **before deploying the updated app**. Then configure the background worker using [the Quick Note setup and verification guide](../docs/QUICK-NOTES.md). Browser kicks work with your current sign-in; filing after the app closes requires migration 009 plus the worker environment and Vault secrets. This release supplies those migrations; it does not automatically apply them to your hosted project.

The browser saves an outbox before clearing the composer. A server acknowledgement means the queue is durable. Until then, reopen Aria in the same browser to resend; clearing browser storage discards unsent entries. Quick Note reserves the existing `gemini-3.5-flash-lite` quota shared with the chat planner and never falls back to the 20/day models. Failed attempts may call the model again, up to five attempts before manual Retry. There is no promise of one provider call across a crash/retry.

## Set up Supabase

1. In SQL Editor, run `supabase/001_aria.sql` once. It creates owner-scoped, read-only approved passages plus persistent quota reservations and search functions. The supplied owner UUID is embedded in the quota function. This migration has not been run remotely.
2. In Authentication → Users, use the owner account with UUID `2b0adefe-04f4-4f39-9332-d0287953096b`. Confirm the user email in the dashboard if needed. Disable public signups under Authentication settings. Never use service-role credentials in the browser.
3. Optional: add a short, non-sensitive passage through Table Editor → aria_chunks. Set owner_id to your UUID, title and source_path to its original note title/path, content to its exact text (maximum 3,000 characters), ai_enabled to true. Leave embeddings empty for keyword search. This is manual seeding, not automated vault sync.

After the initial schema is installed, run `supabase/002_search_questions.sql` in SQL Editor to support natural-language keyword questions, then `supabase/003_starter_note.sql` to import one explicitly approved, non-sensitive overview from `20 Topics/Aria Starter Vault.md`. Both scripts are safe to rerun. The seed is generated by `node tools/prepare-starter-import.mjs` from the repository root; this command only writes a local SQL file. No personal-vault files are scanned. These scripts have been prepared locally; execution and real retrieval must be verified in the user's Supabase project.

In the chat's composer, change General chat to Search my notes and ask “What's included in this starter vault?” Expect a source card for Aria Starter Vault. Keep ENABLE_SEMANTIC_SEARCH=false for this keyword-only test. This imports a snapshot, not ongoing access to the local vault. ## Deploy to Vercel

Push the app code to your chosen GitHub repository (the parent .gitignore excludes vault/ and secrets). Import that repository into Vercel. Set Root Directory to `web`, Framework Preset to Other, Output Directory to `public`, and leave Build/Install commands empty. Use Node 22 or 24. Add the variables from `.env.example` to Vercel Settings → Environment Variables. The real project URL is the origin, without `/rest/v1/`.

Set GEMINI_API_KEY only in server environment variables; no PUBLIC/NEXT_PUBLIC prefix. SUPABASE_PUBLISHABLE_KEY is the public key supplied by you, not a service-role key. Redeploy after changing environment variables.

Test the deployed URL from your restricted network: sign in, ask a general question, then query a seeded note in Search my notes mode. Browser calls only the Vercel origin. The server must be able to reach Supabase and Google's API. Authentication/session and provider responses are never cached.

## Model routing and zero-budget policy

| Model | Purpose | Supplied RPM / RPD |
|---|---|---|
| Gemini 3.5 Flash Lite | Default everyday chat and synthesis | 15 / 500 |
| Gemini 3.1 Flash Lite | Manual alternative | 15 / 500 |
| Gemini 3.8 Flash | Complex synthesis selected manually | 5 / 20 |
| Gemini 3.6 Flash | Comparison | 5 / 20 |
| Gemini 3 Flash | Comparison / compatibility | 5 / 20 |
| Gemini 2.5 Flash | Earlier-model baseline | 5 / 20 |
| Gemini Embedding 2 | Optional semantic retrieval, 768 dimensions | 100 / 1,000; 30,000 TPM |
| DeepSeek | Disabled; no funded budget | No requests |

Model IDs are configurable in lib/models.js AND the SQL quota function. IDs/access can differ from dashboard display labels; an unavailable ID produces a clear error without falling back. Verify actual availability with your account before use. No automatic retries or paid fallback. Vault answers use as many research-planning rounds as needed, plus a final answer; general chat uses one call. Every generation, including planning, reserves quota on the selected model before calling Gemini. There is no additional shared daily app cap. For existing databases, run `supabase/005_remove_app_cap.sql` to remove the previous 50-call cap; fresh installs already omit it. Provider daily limits may reset differently; the app uses conservative rolling windows and counts failed attempts. Usage elsewhere in your Google project is not visible to this app. Tokens are conservatively reserved using UTF-8 request bytes plus the output limit, rather than estimating words. Records contain counts, not prompts; retain recent records and prune old ones periodically through SQL administration.

## Search and automatic sync

Keyword search works with seeded approved chunks. Optional semantic search uses Gemini Embedding 2 for query embeddings when ENABLE_SEMANTIC_SEARCH=true; document chunks must first have embeddings from the same model, 768 dimensions, and embedding_model='gemini-embedding-2'. Do not enable this merely to search an empty database. A bulk importer/embedding job is not part of this starter.

Source excerpts are returned with citations and use the same safe formatted renderer as notes. Citation IDs are checked for existence; their factual support still needs human review. Each search uses lexical rank plus optional cosine similarity, not graph traversal/reranking. Both modes receive conversation memory; Vault mode treats previous answers as context and re-retrieves procedural evidence. The latest 10 chats persist in this browser via IndexedDB; the oldest is deleted when an 11th is created.

### Adaptive research and reasoning

The composer includes a **Concise response** checkbox, remembered in this browser. It asks for a short answer in both general and vault modes while retaining required details and citations. It changes answer style, not research coverage or verification requirements.

Chat uses a streamed response to show **Research activity** while work runs: each search query, returned note titles/paths, gap-checking stages, and answer preparation. This is an activity log, not private model reasoning. It remains available in a collapsed panel under the completed answer. Clients that do not request `application/x-ndjson` still receive a normal JSON response. Interrupted streams and streamed errors are surfaced in the chat; heartbeat frames keep active connections from sitting entirely idle.

Live chat also requests Google's documented thought summaries using `thinkingConfig.includeThoughts: true`. The **Gemini thought summaries** panel shows text marked `thought: true` by the provider as it arrives, grouped by research round or answer preparation. These are provider-generated summaries, not raw internal reasoning or Aria-authored progress messages. Some responses provide no summary; the panel says so rather than inventing one. Thought signatures are discarded. Summaries remain separate from the final answer, source evidence, and conversation history. Planner JSON and incomplete answer text are not displayed as summaries. Final vault answers still pass citation-ID validation before display. See [Google's Generate Content thought-summary documentation](https://ai.google.dev/gemini-api/docs/generate-content/thinking?hl=en).

A timeout now distinguishes no upstream stream data, a stream that stopped sending data, and the overall response deadline. A timeout alone cannot establish whether the cause is model load, network/proxy behavior, or prompt complexity. No automatic retry or model fallback is introduced. Browser disconnects cancel in-flight streaming generation. Deployment is required before these local changes affect a hosted site.

Assistant answers render headings, bold/emphasis, lists, code, blockquotes, simple tables, and HTTP(S) links. The renderer creates DOM elements without interpreting raw HTML. User messages remain literal text. Source excerpts render the same nested steps, colors, links and quotations as notes.

Gemini 3.8 requests use `thinkingLevel: low`, an 8,192-token generation budget, to leave room for reasoning and visible output. Live chat uses Google’s `streamGenerateContent?alt=sse` endpoint, with a 120-second idle timeout that resets when upstream bytes arrive and a shared 270-second generation deadline below the 300-second hosting limit. This replaces the fixed 75-second cutoff for streamed Gemini 3.8 requests. Non-streaming JSON clients retain the earlier 75-second (3.8) / 45-second (other models) provider timeout. These controls follow the [Gemini 3.8 documentation](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash/) and [thinking documentation](https://ai.google.dev/gemini-api/docs/thinking/). Quota reservations include the larger budget. The app distinguishes invalid API keys, model/access errors, provider quota errors, timeouts, and network failures without returning raw upstream error bodies. If Google reports `API_KEY_INVALID`, replace `GEMINI_API_KEY` in the environment actually serving the app and restart/redeploy. Changing local `.env.local` does not update Vercel's environment.

Browser regression coverage for concise preference, live progress before completion, Markdown safety, and mobile width is available through `node tests/workspace-browser.cjs` (uses the same locally installed Playwright/Chrome paths as the existing browser test).

`lib/rag.js` contains the editable `VAULT_SYSTEM` (answer behavior), `RESEARCH_SYSTEM` (search behavior), and research limits. Edit these prompts to change how Aria reasons with retrieved notes; edit the original notes in the Notes editor to correct the procedures themselves. Updating a prompt does not fix contradictory source material.

Vault mode first searches the operator's message, then asks the selected model which information is missing. Aria can request up to four focused keyword searches per round, with no fixed total round or search-count cap. She can follow a relevant procedure named in a retrieved passage, or search for another part of a multi-part request. An empty first search also reaches planning so she can try better terms. Follow-up searches use the same authenticated owner and selected vault as the initial request; the model cannot widen that scope. Only the initial search optionally uses an embedding.

The final answer sees deduplicated passages with stable citation IDs (a catalog of all collected passages, with 180,000 characters of recent complete passages in model context), the original operator message, search coverage, and any research warnings. It can connect ideas and offer labeled suggestions beyond the wording of a note, while keeping company rules and account-specific facts grounded. Explicit operator status such as `Authenticated - Customer asks ...` is accepted as completed identity authentication for the case, while quoted customer claims, third-party authority, and separately required transaction verification remain distinct. Aria has no customer-account or document-sending tools; researching a payment procedure cannot establish whether a payment actually cleared.

The UI reports search and model-call counts. Invalid/truncated plans stop further research with a visible warning; provider/database/quota failures stop the request without retries. Raw planning output and private reasoning are not displayed. The response's `usage` remains the final generation's provider usage; `research.planningCalls` reports additional generation count. Research adds latency and consumes the selected model’s quota. The Vercel function duration is 300 seconds. The browser now advances research one checkpointed operation per request, allowing it to span hosting windows. Refresh restores a Resume control. No SQL migration is needed.

Run `npm test` for mocked retrieval, citation, quota-reservation, and vault-isolation checks. Use `../eval/rag-cases.json` to evaluate actual model behavior after deployment: mocked tests verify orchestration, not the quality of model reasoning or compliance with every prompt instruction.

The selected starter vault remains at ../vault/Aria Knowledge relative to the web folder. The personal vault at D:\Archive\Lumina Records\Lumina Records is not read or changed. The prepared automatic agent pairs local folders with cloud vaults, uses version checks, and preserves conflicting copies; see ../docs/OBSIDIAN-SYNC.md for one-time setup. The cloud cannot directly write to your local drive.

## Vaults and paste import

Run `supabase/004_vaults.sql` after the earlier scripts (001, 002_notes, 002_search_questions, 003). It is safe to rerun. Existing notes move into a vault called "Aria Knowledge".

- **Switching vaults.** Chat: choose "Search my notes", then pick a vault (or "All vaults"). Notes and Import have their own picker. The ＋ button creates a vault.
- **Syncing your own Obsidian vault into a cloud vault:** `node tools/sync-vault.mjs --vault "D:\path\to\vault" --cloud-vault "My Vault" --create-vault` (dry run; add `--apply` to execute). `--vault` is required with `--cloud-vault`. Each cloud vault keeps its own sync state in `.local/`.
- **Paste import** (`/import.html`). Your text is cut only at existing line breaks, never edited. Aria adds metadata outside the original text. The UI adds no section-label text to the body; optional formatting is stored as validated positional hints. The text is checked before saving and each saved note is read back and compared with what was sent. Large pastes become numbered notes. Text that cannot be stored unchanged (NUL characters, \r, broken Unicode, or one unbroken block over about 150,000 characters) is refused rather than altered.
