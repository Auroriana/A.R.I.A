# Aria chat — Vercel starter

Dependency-free static frontend and Node.js API. All browser requests stay on your website origin. Server-side Supabase password login uses an HttpOnly, SameSite cookie; sessions expire after at most one hour and require sign-in again. Owner UUID is checked on every protected request. No API key reaches the browser.

## Set up Supabase

1. In SQL Editor, run `supabase/001_aria.sql` once. It creates owner-scoped, read-only approved passages plus persistent quota reservations and search functions. The supplied owner UUID is embedded in the quota function. This migration has not been run remotely.
2. In Authentication → Users, use the owner account with UUID `2b0adefe-04f4-4f39-9332-d0287953096b`. Confirm the user email in the dashboard if needed. Disable public signups under Authentication settings. Never use service-role credentials in the browser.
3. Optional: add a short, non-sensitive passage through Table Editor → aria_chunks. Set owner_id to your UUID, title and source_path to its original note title/path, content to its exact text (maximum 3,000 characters), ai_enabled to true. Leave embeddings empty for keyword search. This is manual seeding, not automated vault sync.

In the chat's composer, change General chat to Search my notes and ask “What's included in this starter vault?” Expect a source card for Aria Starter Vault. ## Deploy to Vercel

Push the app code to your chosen GitHub repository (the parent .gitignore excludes vault/ and secrets). Import that repository into Vercel. Set Root Directory to `web`, Framework Preset to Other, Output Directory to `public`, and leave Build/Install commands empty. Use Node 22 or 24. Add the variables from `.env.example` to Vercel Settings → Environment Variables. The real project URL is the origin, without `/rest/v1/`.

Set GEMINI_API_KEY only in server environment variables; no PUBLIC/NEXT_PUBLIC prefix. SUPABASE_PUBLISHABLE_KEY is the public key supplied by you, not a service-role key. Redeploy after changing environment variables.

Test the deployed URL from your restricted network: sign in, ask a general question, then query a seeded note in Search my notes mode. Browser calls only the Vercel origin. The server must be able to reach Supabase and Google's API. Authentication/session and provider responses are never cached.

## Model routing and zero-budget policy

| Model | Purpose | Supplied RPM / RPD |
|---|---|---|
| Gemini 3.5 Flash Lite | Default everyday chat and synthesis | 15 / 500 |
| Gemini 3.1 Flash Lite | Manual alternative | 15 / 500 |
| Gemini 3.8 Flash | Complex synthesis selected manually | 5 / 20 |
| Gemini 3.6 Flash | Comparison | 5 / 20 |
| Gemini 3 Flash | Comparison / compatibility | 5 / 20 |
| Gemini 2.5 Flash | Earlier-model baseline | 5 / 20 |
| Gemini Embedding 2 | Optional semantic retrieval, 768 dimensions | 100 / 1,000; 30,000 TPM |
| DeepSeek | Disabled; no funded budget | No requests |

Model IDs are configurable in lib/models.js AND the SQL quota function. IDs/access can differ from dashboard display labels; an unavailable ID produces a clear error without falling back. Verify actual availability with your account before use. No automatic retries or paid fallback. Vault answers use 1–2 research-planning calls plus one final answer (2–3 generation attempts total); general chat uses one. Every generation, including planning, reserves quota on the selected model before calling Gemini. There is no additional shared daily app cap. For existing databases, run `supabase/005_remove_app_cap.sql` to remove the previous 50-call cap; fresh installs already omit it. Provider daily limits may reset differently; the app uses conservative rolling windows and counts failed attempts. Usage elsewhere in your Google project is not visible to this app. Tokens are conservatively reserved using UTF-8 request bytes plus the output limit, rather than estimating words. Records contain counts, not prompts; retain recent records and prune old ones periodically through SQL administration.

## Search and future sync

Keyword search works with seeded approved chunks. Optional semantic search uses Gemini Embedding 2 for query embeddings when ENABLE_SEMANTIC_SEARCH=true; document chunks must first have embeddings from the same model, 768 dimensions, and embedding_model='gemini-embedding-2'. Do not enable this merely to search an empty database. A bulk importer/embedding job is not part of this starter.

Source excerpts are returned with citations and safely rendered as text. Citation IDs are checked for existence; their factual support still needs human review. Each search uses lexical rank plus optional cosine similarity, not graph traversal/reranking. Vault mode omits chat history to avoid reusing stale evidence; phrase follow-up questions explicitly, including current case status. General chat includes bounded history and never claims vault access. Chats stay in browser memory and disappear on refresh or sign-out.

### Adaptive research and reasoning

`lib/rag.js` contains the editable `VAULT_SYSTEM` (answer behavior), `RESEARCH_SYSTEM` (search behavior), and research limits. Edit these prompts to change how Aria reasons with retrieved notes; edit the original notes in the Notes editor to correct the procedures themselves. Updating a prompt does not fix contradictory source material.

Vault mode first searches the operator's message, then asks the selected model which information is missing. Aria can request up to four focused keyword searches per round, for up to two rounds. She can follow a relevant procedure named in a retrieved passage, or search for another part of a multi-part request. An empty first search also reaches planning so she can try better terms. Follow-up searches use the same authenticated owner and selected vault as the initial request; the model cannot widen that scope. Only the initial search optionally uses an embedding.

The final answer sees deduplicated passages with stable citation IDs (at most 24 passages / 60,000 content characters), the original operator message, search coverage, and any research warnings. It can connect ideas and offer labeled suggestions beyond the wording of a note, while keeping company rules and account-specific facts grounded. Explicit operator status such as `Authenticated - Customer asks ...` is accepted as completed identity authentication for the case, while quoted customer claims, third-party authority, and separately required transaction verification remain distinct. Aria has no customer-account or document-sending tools; researching a payment procedure cannot establish whether a payment actually cleared.

The UI reports search and model-call counts. Invalid/truncated plans stop further research with a visible warning; provider/database/quota failures stop the request without retries. Raw planning output and private reasoning are not displayed. The response's `usage` remains the final generation's provider usage; `research.planningCalls` reports additional generation count. Research adds latency and consumes the selected model’s quota. The Vercel function duration is set to 300 seconds for the bounded multi-call flow; no SQL migration is needed for this change.

Run `npm test` for mocked retrieval, citation, quota-reservation, and vault-isolation checks. Use `../eval/rag-cases.json` to evaluate actual model behavior after deployment: mocked tests verify orchestration, not the quality of model reasoning or compliance with every prompt instruction.

The selected starter vault remains at ../vault/Aria Knowledge relative to the web folder. The personal vault at D:\Archive\Lumina Records\Lumina Records is not read or changed. Later cloud-to-local writing needs an opt-in local agent: download pending note drafts, validate paths, preview differences, resolve conflicts, and write into an Inbox. The cloud cannot directly write to your local drive.

## Vaults and paste import

Run `supabase/004_vaults.sql` after the earlier scripts (001, 002_notes, 002_search_questions, 003). It is safe to rerun. Existing notes move into a vault called "Aria Knowledge".

- **Switching vaults.** Chat: choose "Search my notes", then pick a vault (or "All vaults"). Notes and Import have their own picker. The ＋ button creates a vault.
- **Syncing your own Obsidian vault into a cloud vault:** `node tools/sync-vault.mjs --vault "D:\path\to\vault" --cloud-vault "My Vault" --create-vault` (dry run; add `--apply` to execute). `--vault` is required with `--cloud-vault`. Each cloud vault keeps its own sync state in `.local/`.
- **Paste import** (`/import.html`). Your text is cut only at existing line breaks, never edited. Aria adds a small frontmatter header and `##` section labels between lines (shown highlighted in the preview). The text is checked before saving and each saved note is read back and compared with what was sent. Large pastes become numbered notes. Text that cannot be stored unchanged (NUL characters, \r, broken Unicode, or one unbroken block over about 150,000 characters) is refused rather than altered.
